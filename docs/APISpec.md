# API Spec (v1)

## `GET /users/search`
- Query: `nickname`
- Response:
  - `ouid`
  - `nickname`
  - `source`
- 존재하지 않거나 유효하지 않은 닉네임은 404와 한국어 안내를 반환합니다. 인증·점검 등 외부 서비스 오류를 없는 구단주로 분류하지 않으며, 원본 요청 URL·오류 메시지를 화면에 노출하지 않습니다.

## `POST /analysis/run`
- Body:
  - `ouid: string`
  - `match_type: 50|60|52`
  - `window: 5|10|30|null` — 새 화면은 null로 요청해 선택 범위 전체를 분석합니다. 기존 호출의 기본값 30은 호환을 위해 유지합니다.
  - `current_tactic?: object`
  - `squad_feed_id?: string`
  - `include_forfeit_wins?: boolean = false`
  - `include_forfeit_losses?: boolean = false`
  - `start_match_id?: string` — 분석 시작 경기(포함). 미지정이면 조회 가능한 가장 오래된 경기
  - `end_match_id?: string` — 분석 종료 경기(포함). 미지정이면 최신 경기
- Response:
  - `metrics`
  - `issues`
  - `actions`
  - `coaching` — 선수·강화·등록 포지션별 기록과 플레이 교정안

- 같은 선수도 시즌/강화/등록 포지션이 다르면 별도로 집계합니다. 경기 중 위치 이동·포지션 변경이나 코치·특성 발동 여부는 판별하지 않습니다.
- 지표는 성공 합계/시도 합계로 계산하며, 누락된 필드·미출전 교체 선수는 진단에 사용하지 않습니다. 몰수승·몰수패는 기본 제외하며 각각 포함할 수 있습니다. 알 수 없는 종료 유형은 항상 제외합니다. 이전 기록 대비 상승·하락 판정에는 각 5경기와 지표별 최소 시도 수를 요구합니다. 현재 기록의 역할별 플레이 제안은 비교 판정과 분리합니다.
- 임의의 40% 같은 기준은 사용하지 않습니다. 같은 모드·카드·강화·자리의 이전 정상 종료 기록과 비교하며 95% Wilson 구간이 겹치지 않는 상승·하락만 장점·개선점으로 표시합니다. `guidance`는 실제 기록, 비교로 확인한 변화, 플레이와 코치 선택지를 분리해 반환합니다. 감독 모드는 직접 조작을 교정하지 않습니다.
- 추가 외부 API 호출 없이 이미 수집한 경기 기록을 한 번 순회합니다. 집계는 `O(경기 수 × 경기당 선수 수)`, 결과 정렬은 `O(선수·자리 조합 수 × log(조합 수))`입니다.
- 코칭 결과는 분석 스냅샷에 저장해 `/analysis/latest`에서도 동일하게 반환합니다. 30일을 초과한 코칭 상세는 삭제·조회 차단합니다. 기존 DB에는 시작 시 `coaching_json` 열을 추가합니다.
- 선택 조건에 맞는 경기가 없으면 400과 안내를 반환하며, 0으로 채운 분석 스냅샷을 만들지 않습니다. 팀 득실점은 최종 점수(`goalTotalDisplay`)를 우선 사용하고, 슈팅 전환율은 슈팅 득점(`goalTotal`)으로 계산합니다. 60분 이후 실점 비중은 시간이 확인된 실점을 분모로 사용합니다.
- 랭커의 플레이 수치는 같은 공식경기 모드의 실제 경기 프로필이 있을 때만 비교합니다. 랭킹 메타데이터의 승률만으로 유사 랭커를 생성하지 않습니다.

- `coaching.passing`은 팀 전체의 숏·롱·바운싱 롭·드리븐 땅볼·스루·로빙 스루 패스 분석입니다. 선수별 API에는 총 패스만 있으므로 유형을 선수에게 배분하지 않습니다. 패스 방향·좌표는 제공되지 않아 전진 패스 비율/성공률도 계산하지 않습니다.
- 모든 유형과 전체 패스의 성공/시도가 유효한 선택 경기만 같은 분모로 집계합니다. 6유형 합계와 전체 기록의 차이는 `remainder`로 별도 반환하고 종류를 추정하지 않습니다. 차이의 성공 수가 음수이거나 차이의 시도 수보다 크면 해당 경기를 제외합니다. 제외 경기 수를 반환하며 누락을 0회로 취급하지 않습니다. `types`에는 `success_rate`, `usage_share`(유형 시도/전체 시도), `failure_share`(유형 실패/전체 실패), `loss_per_100_passes`(유형 실패/전체 시도×100)를 반환합니다. 분모가 0이면 비율은 `null`이고 유형 비중의 합은 100%보다 작을 수 있습니다.
- `priorities`는 5경기·유형 시도 20회·실패 5회 이상에서 실패 비중이 사용 비중보다 큰 유형을 실패 수 순으로 최대 3개 제시합니다. 표본 기준은 탐색용이며 검증된 최적값이 아닙니다. 유형 난이도·찬스 기여의 차이 때문에 저성공률을 잘못된 선택으로 단정하지 않고 상황별 교정 후보와 성공률·사용량·실패량·팀 슈팅/득점의 재비교를 안내합니다. 감독 모드는 관찰만 안내합니다.
- 패스 유형 수는 고정 6개이므로 추가 집계는 `O(경기 수)`이며 외부 API 호출을 추가하지 않습니다.

## `GET /matches/recent`
- Query: `ouid`, `match_type: 50|60|52`
- 최신 동기화를 확인한 저장 경기 목록을 최신순 최대 100개 반환합니다.
- `items`: `match_id`, `match_date`, `opponent_nickname`, `result`, `score_for`, `score_against`, `match_end_type` (0 정상 종료, 1 몰수승, 2 몰수패)
- `sync_warning`으로 최신 동기화 제한을 안내합니다.

## `POST /analysis/compare`
- Body: `ouid`, `match_type`, `before_match_ids`, `after_match_ids`, `include_forfeit_wins=false`, `include_forfeit_losses=false`.
- 두 그룹은 각각 1~200경기이며 각 ID는 8~128자의 영숫자·하이픈·밑줄입니다. 중복·두 구간의 겹침·해당 사용자/모드에서 조회되지 않는 ID는 거부합니다.
- 최신 경기를 확인한 후 사용자가 지정한 경기만 비교합니다. 실험 등록·시작 시점·고정 경기 수와 연결하지 않으며 기존 실험 데이터를 읽거나 변경하지 않습니다.
- Response: `before`, `after`(경기 수·기간·ID·제외 수), `metrics`(전/후 값·분모·변화량·방향), `strengths`, `improvements`, `note`, 동기화 정보.
- 횟수·득실점은 확인된 경기당 평균, 성공률은 성공 합계/시도 합계입니다. 0회 시도·누락 수치는 null이며 0%로 바꾸지 않습니다. 높은 점유율·드리블 거리·선방 횟수를 자동으로 개선으로 분류하지 않습니다.
- 상승/하락은 선택한 두 그룹의 관측값 변화입니다. 상대·구성·난이도 차이 또는 전술·코치 변경의 인과 효과로 단정하지 않습니다. 계산은 수집된 데이터를 재사용해 `O(경기 수 × 선수 수)`입니다.

## 경기 표본 선택
- 최신순 목록에서 종료~시작 경기를 모두 포함한 뒤 종료 유형을 필터링합니다. window=null이면 그 범위 전체를 사용하며, 고정 개수로 자르거나 범위 밖 경기로 채우지 않습니다. 같은 시각의 경기도 match_id로 구분합니다.
- 시작·종료 ID가 해당 사용자·모드에서 조회되지 않거나 종료가 시작보다 오래되면 400으로 거부합니다. 최신 전체 구간으로 대체하지 않습니다.
- `sample_selection`에 선택 조건·시작 시각·범위 안 경기 수·정상/몰수승/몰수패 표본 수를 반환합니다. `recent_matches`는 실제 선택 표본의 최신 5개입니다.
- 그래프·선수 코칭·피드 대조에 같은 선택 표본을 사용합니다. 전후 비교도 정상 종료 경기를 기본으로 하며 몰수승·몰수패를 각각 포함할 수 있습니다. 몰수 포함 시 경기 길이/집계 차이를 함께 고려합니다.
- `analysis_json`에는 분석 시점의 결과·표본 조건을, `coaching_json`에는 코칭을 분리 저장합니다. 재조회 시 새 경기로 당시 표본을 재구성하지 않습니다. 둘 다 30일 정리에 포함됩니다. `/analysis/latest`는 사용자/모드/window의 마지막 실행 결과이며 선택 조건이 함께 반환됩니다.

### 전체 경기 지표 시각화
- `coaching.domains`는 `shooting`, `defending`, `carrying`, `discipline`, `overview` 영역의 기록·경기별 추이를 반환합니다. 패스는 기존 `coaching.passing`을 사용합니다.
- 슈팅: 유효 비율, 전체·박스 안팎·헤딩·프리킥·PK 득점 전환율, 상세 슛 종류별 득점·유효 비율·시도 비중·미득점 기여 비중, 선수 득점·도움, 경기 결과의 팀 득점·자책골·승부차기 슈팅 기록. 종류별 상세와 집계 기록은 서로 다른 출처이므로 일치시키거나 합산하지 않습니다. 미정의 종류 코드는 추정 이름 대신 코드 그대로 표시합니다.
- 수비: 팀 태클·블록 성공률, 선수 인터셉트·디펜딩 합산, 상대 슈팅·실점, 60분 이후 실점 비중과 득실 시간대. `goalTime`은 공식 초 단위와 전후반·연장전 오프셋으로 해석하며 승부차기는 일반 슈팅 전환율·위치·시간대에 포함하지 않고 승부차기 시도 기록으로 분리합니다.
- 볼 운반·경합: 선수 드리블·볼 소유·공중볼 경합 성공률과 선수·팀 드리블 거리(야드). 실제 응답의 `ballPossesionSuccess`와 문서의 `ballPossesionSuc`를 모두 지원합니다.
- 경기 운영·종합: 오프사이드·파울·팀/선수 카드·코너킥·부상, 승률·득실·점유율·평점. 단위가 다른 평균은 서로 같은 막대로 비교하지 않고 자체 척도의 추이로 표시합니다.
- `metrics`는 `value`, `unit`, `observed_matches`, `history`, `status`, `minimum_trials`, `guide`를 포함합니다. 비율에는 `success`/`trials`/`failures`, 평균에는 `total`을 추가합니다. 누락·음수·비수치·성공>시도는 제외하고 0회 시도 비율은 `null`입니다. 충분 표본은 기록 5경기 이상과 지표별 시도 수로 정하지만 정상·문제 판정 기준을 뜻하지 않습니다.
- `shot_map`은 유효한 원본 0~1 좌표만 포함합니다. 선수 이동·수비 위치 그림은 기록이 아닌 교정 설명용 개념도입니다. 골키퍼 선방·압박·선수별 패스 방향 등 제공되지 않는 기록을 생성하지 않습니다.
- `players.measurements`에 득점 전환·블록·볼 소유·공중볼 경합을 추가하고 `observations`에 횟수·거리·평점을 반환합니다. 비교 기준이 없는 항목의 `reference`는 `null`이며 저조 판정을 생성하지 않습니다. 선수 슛 종류 `shot_types`는 상세 선수·강화와 해당 경기의 등록 자리가 유일하게 연결되는 경우만 합산합니다.
- 추가 집계는 경기·선수·슈팅 이벤트를 순회하고 종류별 경기 추이를 생성하는 `O(M×P+S+M×T)` (T는 슛 종류 수)입니다. 외부 호출을 추가하지 않으며 종류별 전체 분모를 미리 계산해 재사용합니다.

### 공개 스쿼드피드 연결
- `GET /squad-feeds?nickname=...&page=1`: 작성자 닉네임이 정확히 일치하는 공개 피드 목록(`items`, `page`, `has_more`, `fetched_at`)을 반환합니다. 닉네임 2~100자, 페이지 1~20이며 페이지별 10개입니다. 목록에 포함된 다른 작성자의 부분 일치 결과는 제외합니다.
- `GET /squad-feeds/{feed_id}`: 공개 피드의 정규화된 전술·선수·기본/획득 특성·훈련코치·개인 전술·참여도를 반환합니다. ID는 영숫자 8~32자만 허용하고 외부 요청 주소는 넥슨 공식 호스트로 고정합니다. 계정 번호·작성 내용·댓글은 가져오지 않습니다.
- 필드 상태는 `present`(저장값), `unset`(피드에서 미설정), `missing`(미제공), `invalid`(형식·범위 오류)로 구분합니다. `-2` 특성·코치 값은 피드 미설정으로 처리하고 실제 게임 미장착으로 판정하지 않습니다. 개인 전술의 null을 기본 전술로 채우지 않습니다. 미정의 코드에는 추정 이름을 붙이지 않습니다.
- 표시 이름과 개인 전술 코드 표는 공식 사이트의 2026-10-16 클라이언트 표기를 기준으로 `services/data/squad_feed_labels.json`에 보관합니다. 코치의 등급·레벨과 게임 슬롯 A-3 등은 제공된 값이 없어 생성하지 않습니다.
- `POST /analysis/run`의 선택 필드 `squad_feed_id`로 피드를 연결합니다. 분석 실행 시 공개 상태를 새로 확인하며, 실패하면 `coaching.squad_feed.status=unavailable`을 반환하고 피드 설정을 재사용하지 않습니다. 경기 기록 코칭은 계속 제공합니다. 실패한 상세 캐시도 무효화합니다.

### 경기·설정 종합 코칭과 특성 그림
- 연결된 선수의 `comparisons[].plans`에 근거 지표(`evidence`), 함께 검토한 설정(`settings`), 변경 전후 값과 플레이 교정(`actions`), 다음 경기 확인 방법(`verification`), 판단 범위(`limitation`)를 반환합니다. `priorities`는 서로 다른 선수·자리에서 최대 3개를 제시하고 `rule_version=feed_history_evidence_v2`을 저장합니다. `observation`은 비교 근거로 교정을 제시하지 않는 기록 확인 상태이며 강제로 설정 변경을 만들지 않습니다.
- 선수 설정 코칭은 같은 카드·강화·자리의 이전 정상 종료 경기 대비 뚜렷한 하락이 확인된 지표만 사용합니다. 임의의 볼 소유·태클·패스 성공률 및 +5%p 목표로 교정을 생성하지 않습니다. 타겟맨 코치의 공식 개인 전술 선행 조건은 설정 사실로만 구분하며, 근거 없는 성과 문제로 분류하지 않습니다. 누락된 설정을 기본값으로 채우지 않습니다.
- `team_plans`는 매 경기의 선발 11명 카드·강화·자리가 모두 동시에 일치한 표본만 새로 집계합니다. 서로 다른 경기의 선수들을 합쳐 선발 일치로 판정하지 않습니다. `matched_roster_sample_count`가 이 경기 수이며 최소 5경기와 관련 지표 표본이 있어야 팀 설정 실험을 생성합니다. 팀 패스 유형을 개별 선수에게 배분하지 않습니다. 기존 `checks`/`team_checks`는 응답 호환용으로 남기며 새 화면의 종합 처방은 `plans`/`team_plans`를 사용합니다.
- 기본 특성 원문 `intrinsic_traits`를 보존하고 그림용 `intrinsic_features`를 추가합니다. 기본·획득 특성 및 훈련코치의 feature는 `code`, `label`, `known`, `icon_url`을 제공합니다. 공식 클라이언트의 2026-10-19 그림 경로를 확인해 코드별 공식 CDN URL을 생성하며, 미정의 코드는 URL을 만들지 않습니다. 정규화 상세 캐시는 v4로 분리합니다.
- 화면에서는 그림 버튼을 누르면 이름이 펼쳐지고 다시 누르거나 Escape로 닫힙니다. 키보드 Enter/Space도 지원합니다. 알 수 없는 코드나 그림 로딩 실패에는 대체 표시를 사용하고 이름 확인은 유지합니다. 그림은 지연 로딩하며 특성별 추가 API 조회를 하지 않습니다.
- 추가 진단은 이미 선택한 경기와 선수 집계를 재사용합니다. 선발 일치 판정과 팀 고정 유형 재집계는 `O(M×P)`, 선수 처방은 `O(R)`이며 필드·규칙 수는 고정입니다. 우선순위 정렬은 `O(R log R)`입니다. 별도 외부 AI 호출은 추가하지 않습니다.

### 경기장 선수 선택과 통합 분석 화면
- `coaching.latest_lineup`은 선택된 분석 표본의 가장 최근 경기 1개에 대한 `match_id`, `match_date`, `players[{sp_id, sp_grade, sp_position}]`입니다. 미출전 후보·중복 기록은 기존 집계와 같은 규칙으로 제외합니다. 서로 다른 경기의 최다 출전 선수를 합쳐 11명을 만들지 않습니다. 경기 자료가 없으면 null이며, 이전 스냅샷에 이 필드가 없으면 재진단을 안내합니다.
- 화면은 연결한 피드의 저장 선발과 최신 분석 경기의 등록 자리 배치를 각각 선택할 수 있습니다. 선수 카드를 누르면 같은 카드·강화·자리의 기록과 습관, 전체 저장 설정, 종합 코칭을 보여줍니다. 피드에 유효한 `x`, `y`가 있으면 저장 위치를 그대로 반영하며, 경기 기록 모드에서는 등록 포지션별 위치를 사용합니다. 경기 중 이동 좌표는 제공되지 않습니다. 미대조·다른 자리 기록을 현재 자리로 합치지 않습니다.
- 획득 특성 전체와 훈련코치 전체를 별도 분류·개수와 함께 표시합니다. 선수 상세 상단에 전체 장착 목록을 한 번 표시하며, 설정 탭과 종합 코칭에서 같은 그림을 반복하지 않습니다. 벨링엄 실데이터는 획득 특성 66/22, 훈련코치 12/30/44로 확인했습니다.
- 선수 리포트와 플레이 습관 메뉴는 `/players`의 ‘선수·플레이 분석’으로 통합합니다. ‘경기장·선수 분석’과 ‘팀 플레이 습관’을 같은 메뉴에서 전환합니다. 기존 `/habits` 진입은 통합 화면의 습관 보기로 연결하고 주소를 `/players`로 정리합니다.
- 선수 대조 사전은 `O(P+R)`로 만들고 선택한 한 명의 상세만 렌더링합니다. 전체 성과표는 펼칠 때 마운트합니다. 최신 경기 선택은 `O(M)`으로 외부 요청을 추가하지 않습니다.

### 분석 화면과 단위 (2026-10-20)
- 피드 선수의 `pitch_position`은 공식 피드의 `x`, `y`를 `{status: "present", value: {x, y}}`로 보존합니다. 둘 중 하나라도 없으면 `missing`, 숫자가 아니거나 비유한 값·0~100 범위 밖이면 `invalid`입니다. 좌표 0은 유효하며 카드의 원래 포지션으로 저장 위치를 추정하지 않습니다. 이전 캐시가 좌표 없이 재사용되지 않도록 상세 캐시 키는 v4입니다.
- 세로 경기장에서는 저장 좌표에 공통 변환 `left=6+0.88*x`, `top=6+0.88*(100-y)`를 적용합니다. 선수별 간격을 균등하게 재배치하지 않습니다. 피드 좌표가 없는 선수와 경기 등록 포지션 모드는 명시적인 포지션 좌표표를 사용하며, 알 수 없는 포지션은 임의의 자리에 놓지 않습니다. 피드 좌표는 최신 경기 배치로 재사용하지 않습니다.
- 선수 배치 계산은 `O(P)`입니다. 다른 자리 기록 판별은 배치 키의 Set을 한 번 만든 뒤 `O(P+R)`에 처리합니다. 추가 외부 요청은 없습니다.
- 경기 분석은 ‘선수 분석 / 팀 기록 / 팀 전술’로 전환합니다. 공통 출처·판단 기준·피드의 과거 경기 사용 미확인은 ‘분석 안내’ 한 곳에 모으고 표본 부족·연결 불일치는 해당 항목에 남깁니다.
- 슈팅 지도는 골문을 위로 놓은 공격 진영 반코트를 기본으로 표시합니다. 좌표를 반코트 경계로 강제 이동하지 않으며, 자기 진영 슈팅이 있으면 그 개수를 표시하고 전체 경기장으로 전환해 원래 좌표를 확인할 수 있습니다. 승부차기 제외 규칙은 동일합니다.
- 거리의 API 단위와 저장 스냅샷은 yards를 유지합니다. 웹의 선수 합계·경기당 거리 및 팀 지표·추이 값은 모두 `yards * 0.9144`로 계산한 m로 표시합니다. 레이블만 변경하거나 이미 저장된 값을 두 번 환산하지 않습니다.
- 일반 안내의 반복 문장을 줄이고 ‘유효 슈팅’, ‘수비수에게 막힌 슈팅’, ‘드라이브 땅볼 패스’, ‘로빙 패스’ 등 공식 홈페이지에서 확인한 표현과 일반 축구 용어를 사용합니다. 공식 특성·훈련코치 이름은 원문을 유지합니다.

- 2026-10-20 공식 매치 문서에는 여전히 슈팅 유형 1~12만 정의돼 있습니다. 최신 경기 `6ad6ed859cda903dfffc22f4` 재조회에서 벤제마 +10의 type=14 득점을 확인했으나 명칭은 반환되지 않았습니다. 코드 14는 ‘종류 미확인 슈팅 · 코드 14’로 유지하고 특정 슈팅 이름을 추정하지 않습니다.

### 경기별 상대 비교와 교정안 분리 (2026-10-20 추가)
- 분석 응답의 `selected_matches`는 해당 분석에 실제 선택된 모든 경기 목록입니다. 기존 `recent_matches`의 최근 5경기 요약은 유지합니다. UI의 ‘경기별 분석’에서 이 목록 중 하나를 선택합니다.
- `GET /matches/{match_id}/review?ouid=...&match_type=60`은 해당 ouid·모드·30일 보관 범위의 저장 원문을 확인한 뒤 양측 기록을 비교합니다. 관계없는 경기·모드·만료 기록은 404입니다. 선수 식별·패스·슈팅·수비·점유율·오프사이드·파울과 양측 슈팅 지도를 제공합니다. 누락·잘못된 성공/시도 수·시도 0은 성공률 0%로 대체하지 않습니다.
- 정상 종료한 두 참가자의 비교 가능한 성공률에서 5%p 이상 차이가 있는 항목을 최대 3개씩 ‘앞선 점 / 다음 경기 점검’으로 제시합니다. 이는 해당 상대와의 관측 차이이며 적정 성공률·실력 차이·승패 원인을 추정하지 않습니다. 몰수 경기는 종료 전 기록만 표시하고 우열 판단·교정 제안은 만들지 않습니다.
- 경기 결과는 `goalTotalDisplay`, 슈팅 기록상 득점은 `goalTotal`을 구분합니다. `score_for_display`, `score_against_display`를 최근/선택 목록에 추가하고 최종 점수 표시에서 우선 사용합니다. 두 값이 다르면 경기 상세에서 차이를 표시하며 원본 지표·코칭 집계는 바꾸지 않습니다.
- 상대와 본인의 현재 시즌 1대1 순위는 공식 데이터센터의 닉네임 검색 결과에서 정확히 일치하는 이름만 사용합니다. ouid의 현재 닉네임을 공식 basic API로 확인합니다. 공식 페이지에 명시된 1~10,000위 이외 상태와 통신/해석 실패를 구분합니다. 역대 최고 1대1 등급은 maxdivision의 matchType=50 및 공식 division 메타데이터로 표시하고 달성일을 붙입니다. 현재·경기 당시 등급으로 대체하거나 강약 판정에 사용하지 않습니다.
- 프로필 조회는 선택한 경기의 두 구단주만 병렬 요청하며 10분 캐시(등급 조회 실패 1분), 등급 메타데이터는 하루 캐시를 사용합니다. 프런트는 탭 내 이미 본 경기 응답을 재사용하고 이전 요청이 늦게 도착해도 현재 선택을 덮지 않습니다. 경기 수만큼 일괄 외부 요청하지 않습니다. 선수 이름은 기존 공식 메타데이터 캐시를 재사용합니다.
- ‘선수 성과’의 최다 출전 카드를 제거하고 찬스 제공 선수 → 슈팅 선수 화살표로 콤비 방향을 표시합니다. 선수 성과 자체의 출전 횟수는 유지합니다.
- 시즌·강화 배지를 얼굴 바깥에 배치합니다. 모든 자리에서 사진 → 시즌·강화 → 전체 이름 순서를 사용합니다. 센터백 전용 상단 라벨·말줄임을 제거하고 좁은 화면에서는 이름을 줄바꿈하며 세로 여백을 확보합니다. 피드의 상대 좌표와 포지션 배치 함수는 변경하지 않습니다.
- 슈팅 정보는 지도 아래 고정 너비 영역에 표시해 화면 가장자리에서 잘리지 않도록 합니다. 점의 터치 영역을 확대하고 화면 좌표에서 22px 이내의 가장 가까운 점을 선택해 투명 터치 영역이 다른 선수를 가로채지 않게 합니다. 겹친 점은 선수·시간 선택 목록 및 44px 이전/다음/닫기 버튼으로 확인할 수 있습니다. 점 선택·포인터 이동에는 API 호출이 없습니다.
- 임의의 태클 40%·패스 기준 등으로 교정안을 만드는 실행 경로를 제거했습니다. 실제 비교 기록이 없는 막대에는 기준선을 표시하지 않습니다. 이전 버전 스냅샷의 코칭·기준·교정안은 반환하지 않으며 새 캐시 키를 사용합니다.
- ‘전술 처방’에서 경기 분석 전체 컴포넌트를 반복 렌더링하지 않습니다. 선택한 선수의 다음 경기 교정안 한 개와 기록 확인 링크를 보여주고 기존 경기 전체 교정안은 별도 접기에서 유지합니다. 자세한 기록·팀 지표·성과·한 경기 비교는 선수·플레이 분석에서 확인합니다.
- 배치와 콤비 렌더링은 기존 O(P), O(C)를 유지합니다. 슈팅 선택은 기존 인덱스 선택 O(1)에서 좌표 최근접 확인 O(S)로 바꿔 밀집 지점의 오선택을 방지하며, 좌표 투영은 메모이제이션해 재사용합니다. 한 경기 지표 비교는 고정 지표 수 K 및 슈팅 S에 대해 O(K+S)이며 선택한 경기만 처리합니다.

### 이전 실측 경기 기반 비교 코칭 (2026-10-20)
- `coaching_version=empirical_history_v2`. 닉네임만으로 경기 기록 분석과 이전 경기 비교를 이용할 수 있습니다. 공개 피드는 선택 사항이며, 팀·개인 전술/특성/훈련코치 설정을 함께 확인하는 데 필요합니다.
- 이전 구간은 현재 선택한 가장 오래된 경기보다 앞선 같은 모드의 정상 종료 경기 중 최대 30개입니다. 선택 경기 ID와 날짜가 겹치는 경기·몰수 경기·날짜 미확인 경기는 비교 대상에서 제외합니다. 선수 코칭은 같은 카드·강화·등록 자리끼리 집계합니다.
- `comparison_scope`에 현재·이전 정상 종료 경기 수와 시작/종료 일시를 반환합니다. 몰수 포함 옵션은 조회 목록·기록에 적용하고, 코칭 비교 양쪽은 정상 종료로 맞춥니다.
- `measurements[].comparison`, `comparisons`에 현재/이전 성공·시도 합계, 시도가 관측된 경기 수·기간, 성공률, 95% Wilson 구간, `gap_pp`, `status`를 반환합니다. 성공률은 경기별 비율 평균이 아닌 성공 합계/시도 합계입니다.
- 양쪽 각 5경기 및 지표별 최소 시도 수를 충족하고 구간이 겹치지 않는 하락(`lower`)만 교정 후보로 사용합니다. 표본 요건은 비교 불확실성을 줄이기 위한 조건이며 적정 성과 기준이 아닙니다. 시도가 없거나 필드가 누락된 값은 0%로 바꾸지 않습니다. 차이가 불확실하거나 비교 기록이 없으면 지표만 표시하고 `findings`, `issues`, `actions`, 피드 `priorities`는 비워 둡니다.
- 팀 진단의 `benchmark`는 실제 비교 가능한 이전 성공률만 포함합니다. 랭커 기록이 없는 항목을 고정값/프록시로 대체하지 않습니다. 이전 관측값은 정상 기준·달성 목표·효과 예측이 아니며, 구간 차이만으로 원인을 확정하지 않습니다. 임의의 수치 목표, 설정 델타, 예측 신뢰도를 생성하지 않습니다.
- 팀 긴 패스 처방은 현재·이전 구간 모두 선발 11명 카드·강화·자리가 동시에 일치한 정상 종료 경기끼리 비교합니다. 선수 한 명의 수치로 팀 폭·깊이를 낮추던 호환용 `team_checks`는 빈 배열로 유지합니다.
- 추가 외부 경기 조회 없이 저장된 자료를 사용합니다. 저장 경기 N개의 이전 구간 선택·정렬은 `O(N log N)`, 현재/이전 집계는 `O((M+H)P+S)`이며 실제 집계에 사용하는 이전 경기 H는 최대 30개로 제한합니다. 선수별 과거 목록을 반복 검색하지 않고 카드·강화·자리 사전으로 대조합니다.
