# 비교 그래프와 최근 경기 추이의 집계 기준

이 문서는 2026-10-29 업데이트까지의 집계·표시 정의를 기록한다.

## 상대 비교

- 몰수 경기의 중단 전 기록도 포함하며, 같은 경기의 양쪽에 유효한 성공·시도 값이 있는 항목을 짝지어 비교한다.
- 성공률은 성공 합계 / 시도 합계이며, 차이는 %가 아닌 %p다.
- 같은 출발점과 눈금의 나·상대 막대, 수치 차이를 카드 하나에 표시한다.
- 슈팅 지역·상황 7개, 전체·유형별 패스 7개, 태클·블록 2개의 성공률을 비교한다. 각 지표는 양쪽 모두 시도가 있는 같은 경기만 집계한다.
- 유효 기록 5경기·시도 20회 이상인 항목의 관측 성공률 차이를 비교한다. 화면 표시 정밀도 이상으로 앞선 항목과 낮은 항목을 각각 차이 큰 순 최대 3개 표시한다. 이는 통계적 유의성이나 실력 차이의 판정이 아니다. 해당 항목이 없으면 빈 설명이나 고정 다섯 그래프를 표시하지 않는다.

## 최근 경기 추이

- `/tracking`에서 최근 경기 추이를 제공한다.
- 몰수승·몰수패를 포함한 최근 30경기를 시간순으로 표시한다. 각 점은 해당 경기까지의 최근 최대 30경기의 이동 집계다.
- 성공률은 이동 구간의 성공 합계 / 시도 합계, 횟수·거리·평점·점유율은 유효 경기의 평균이다.
- 초반에 과거 기록이 30경기 미만이면 확보된 경기만 사용하고, 점을 선택하면 실제 집계 경기 수를 표시한다.
- 미래 경기와 누락·모순 수치를 넣지 않는다. 몰수 경기의 결과는 승률에, 실제 플레이 기록은 해당 지표에 포함한다. 없는 기록은 0으로 만들지 않는다.
- 화면 아래 시점 선택 목록과 이전·다음 버튼으로 모바일에서도 정확히 선택할 수 있다.
- 같은 최신 30경기 집계와 마지막 점의 수치가 일치해야 한다. 측정 단위와 계산 함수는 경기 분석과 공유한다.

## 랭커 평균

- 공식 1대1 랭킹 중 상위 수집 대상 20명을 기준으로 실제 경기 기록이 연결된 인원만 계산한다.
- 각 랭커의 최근 공식경기 최대 30경기(몰수 경기의 실제 기록 포함)로 지표를 먼저 계산하고, 랭커별 지표의 산술평균을 구한다. 경기 수 가중 평균이 아니다.
- 지표별로 실제 기록이 없거나 시도 0회인 성공률은 해당 평균에서 제외한다. 유효한 0%는 포함한다.
- 목록 인원, 평균에 참여한 인원, 경기 기록 수, 지표별 참여 인원을 구분한다. 두 랭커가 같은 경기에 참여하면 개인별 기록 두 개이며 고유 경기 한 개다.
- 사용자와 랭커 모두 몰수 경기의 실제 기록을 포함한다. 사용자는 공식경기·공식 친선 합산 최근 30경기이며 랭커는 공식경기 기준이다.
- 경기 종합·패스·슈팅·수비·드리블·경합·경기 운영은 기존 경기 분석과 동일한 집계 모듈을 사용한다. 거리는 m로 변환한다.
- 수치의 높고 낮음만으로 원인이나 실력 차이를 단정하지 않는다. 평균 산정 기준에서 참여 랭커와 기록 수를 확인할 수 있다.
- 평균 결과는 집계 시각과 경기 범위를 포함하여 캐시하며, 자동 수집 완료 후 새로 계산한다. 공개 조회마다 20명 전체를 다시 수집하지 않는다.

## 계측과 호환성

- 기존 전후 구간 비교 화면은 주 메뉴에서 제거했다. 과거 `before_after_*` 이벤트는 새 경기 흐름의 사용량으로 합산하지 않는다.
- 경기 흐름 새로 갱신은 실제 `run_analysis` 완료로 기록된다. 단순 조회는 기존 `/tracking` 페이지뷰·탭 이벤트이며 갱신 완료와 다르다.
- 기존 구간 비교 API·자료형은 호환성을 위해 보존하지만 현재 화면에서는 사용하지 않는다.

## 맞춤 코칭과 변화 요약

- 맞춤 코칭·팀 분석·랭커 비교는 분석 결과에 포함된 동일한 랭커 평균 스냅샷을 사용한다.
- 실제 랭커별 값의 사분위수(가운데 50%) 범위 밖인 지표를 강점·보완 후보로 선정한다. 고정 성공률 기준을 사용하지 않으며, 원인·실력 차이의 통계적 검정 결과를 뜻하지 않는다.
- 점유율·거리·인터셉트 횟수·패스 유형 사용 비중 등 맥락 의존 지표는 좋고 나쁨으로 분류하지 않는다. 실점·파울 등은 낮을수록 좋은 방향으로 판단한다.
- 비슷한 원인의 지표는 묶어 표시한다. 승률·평점 차이만으로 구체적인 전술을 처방하지 않는다. 도움 횟수 차이는 찬스 생성 조언으로 연결하며 슈팅 정확도 부족으로 해석하지 않는다.
- 선수별 실패 횟수는 점검할 자리를 찾는 참고값이다. 선수 개인의 성공률을 팀 단위 랭커 평균과 비교하지 않는다. 저장된 피드는 작성자와 모드가 일치할 때만 제안에 참고한다.
- 차이가 좋은 방향이면 파랑, 나쁜 방향이면 빨강, 중립 지표·표시 정밀도 미만의 차이는 회색이다. 모든 숫자 증가를 향상으로 표시하지 않는다.
- 흐름 상단은 실제 시계열 중 처음~최근 변화가 시계열 표준편차보다 크고 표시 정밀도 이상인 최대 4개를 표시한다. 같은 집계 경기 수의 점이 5개 이상이면 그 구간을 우선하며, 그렇지 않으면 확보된 구간과 시작·끝 집계 경기 수를 명시한다. 각 시점의 유효 기록 5경기 이상(성공률은 시도 20회 이상)인 연속 구간만 요약하며, 드문 유형의 소수 시도 변동을 강조하지 않는다. 통계적 유의성을 의미하지 않는다.
- 이동 집계는 경기마다 지표를 한 번 계산하고 누적 합과 제한된 큐를 갱신한다. 창마다 다시 모든 경기를 집계하는 중복 연산을 줄인다. 랭커 분포 계산은 최대 20명의 지표를 정렬하므로 O(지표 수 × 20 log 20)이며, 공개 조회는 캐시를 재사용한다.

## 경기 지표 점수 v4: 유형·사용 비중

- 지표별 실제 랭커 상위 10%를 100점 기준으로 하고, 표준편차 1만큼의 불리한 차이를 10점으로 환산해 1~100점으로 제한한다. 랭커 평균을 90점으로 고정하지 않는다.
- 패스는 짧은 패스·긴 패스·바운싱 롭·드라이브 땅볼·스루·로빙 스루와 미분류 기록을 나눠 계산한다. 유형별 성공률 점수에 해당 사용 비중을 가중한다. 전체 패스 성공률은 유형 점수가 있을 때 요약값으로만 보여 중복 가산하지 않는다. 유형 점수가 하나도 없을 때만 전체 성공률을 대체 기준으로 사용한다.
- 미분류 기록은 같은 관측 경기의 전체 성공·시도에서 여섯 유형 합계를 뺀 값이다. 실제 종류를 추정하거나 점수에 가산하지 않고 성공률·비중만 표시한다.
- 사용 비중을 높을수록 좋은 별도 점수로 평가하지 않는다. 같은 가중치를 경기 기록과 랭커 비교 점수에 적용해 실행 성과를 비교한다. 따라서 랭커 영역 평균은 선택한 경기의 시도 구성을 반영한 비교값이다. 실제 사용 비중도 별도로 나란히 표시한다.
- 슈팅은 정확도, 지역별 마무리, 유형별 마무리의 세 묶음을 같은 비중으로 계산한다. 지역·유형 묶음 안에서는 시도 비중을 사용한다. 유형·지역 점수가 있으면 전체 득점 전환율은 요약값으로 이동한다. 박스 안·밖 비중은 같은 경기들의 관측이 일치할 때만 산출한다. 헤딩·PK·프리킥은 슈팅 유형 기록을 사용하며 겹치는 상황 분류를 재가산하지 않는다.
- 수비는 태클·블록 성공과 실점 억제(실점·허용 슈팅)를 같은 비중의 묶음으로 계산한다. 인터셉트·선방/골 차단 횟수와 60분 이후 실점 비중은 참고 기록이다. 시간대 비중이 낮으면 앞선 시간대 실점 비중이 높아질 수 있어 그 자체를 좋은 수치로 채점하지 않는다.
- 드리블·볼 소유·공중볼 경합 성공률을 각각 표시하고 같은 비중으로 점수에 반영한다. 능력별 시도량도 경기당 횟수로 표시한다. 서로 겹칠 수 있는 시도 횟수를 합쳐 가짜 사용 비중으로 만들지 않는다. 선수·팀 드리블 거리는 m 단위 참고 기록이며 점수 보너스를 주지 않는다.
- 경기 운영은 파울·오프사이드의 실제 기록을 유지한다. 종합은 다섯 영역의 평균이다.
- 지표별 유효 5경기·성공률 20회 시도·비교 랭커 5명 이상일 때 점수를 만든다. 지표마다 같은 조건의 랭커 기록을 사용한다. 미달 항목도 성공률·시도 비중은 표시하되 점수는 ‘—’로 두고 가산하지 않는다. 자료가 없는 값을 0점으로 채우지 않는다.
- 점수에 반영할 수 있는 항목들의 가중치를 묶음 안에서 다시 정규화한다. 차이 영향 = (지표 점수−해당 랭커 평균 점수)×최종 가중치. 반올림으로 화면상 합계에 작은 차이가 있을 수 있다.
- 세부 화면은 점수·성공률·사용/시도량·추천 행동을 표시한다. 영역 총점 차이와 점수 영향 표시는 제거하고 개별 원시 지표의 차이만 유지한다. 평균·표준편차·원인 확정 여부 등에 대한 안내 문단은 제거했다. 슈팅 유형과 참고 기록은 탭으로 구분하고, 유형 목록은 사용 비중이 큰 순으로 표시한다.
- 추천은 원래 수치의 실제 랭커 일반 범위와 가중 차이 영향을 사용한다. 많이 쓰는 유형의 실행 약점을 우선하며, 사용량만으로 문제를 만들지 않는다.
- 캐시 버전을 v5로 바꿔 예전 11개 지표 프로필과 새 유형·사용량 프로필이 섞이지 않게 했다. 원자료는 기존 저장 경기에서 재집계하며 추가 넥슨 호출 없이 계산한다.
- 지표당 랭커 표본 정렬 O(R log R), 전체 O(K×R log R)이다. 상세 클릭은 이미 분석한 결과를 사용하며 추가 API 조회가 없다.


## 팀·선수 비교 화면 (2026-10-28)

- 팀 세부 지표는 comparison_metrics.all과 ranker_benchmark.groups의 같은 ID를 연결한다. 거리의 m 환산, 경기당 횟수와 성공·시도 합계는 기존 카탈로그 정의를 그대로 사용한다. 값이 없는 비교 기록은 0으로 채우지 않는다.
- 슈팅의 사용 비중은 랭커별로 계산한 뒤 같은 가중치로 평균한다. 사용 비중·거리·실점 시간대 분포는 중립 지표이며 차이를 표시해도 강점/보완 판정에는 넣지 않는다.
- 영역별 강점·보완점은 전체 코칭의 상위 3개 제한과 별개로 같은 영역의 실제 사분위 범위를 벗어난 기록을 최대 두 개씩 표시한다. 전 영역에서 승률은 코칭 대상에서 제외한다.
- 선수 비교는 카드·강화·포지션별 기록을 선택한다. 서로 다른 자리에서의 기록을 임의로 합치지 않는다. 합계와 각 지표의 실제 관측 경기 수, 경기당 기록과 합산 성공률을 함께 보여준다. 출전 시간은 제공되지 않아 90분당 기록을 만들지 않는다.
- 드리블 거리는 0.9144를 곱해 m로 환산한다. 시도 0회 성공률은 ‘—’, 유효한 성공 0회는 0%다. 한쪽에만 있는 기록도 반대쪽에 0을 채우지 않는다.
- 선수 비교에는 공격/패스·드리블/수비·경합/전체 분류가 있다. 첫 화면은 출전 기록의 득점 합계가 많은 서로 다른 두 선수를 선택한다.
- 슈팅 지도는 선수와 유형을 조합한다. 선수 필터는 같은 선수의 시즌·강화를 함께 조회하며 카드 ID의 선수 번호를 사용한다. 선수 변경 시 유형과 선택된 점을 초기화한다. 유형별 수치는 해당 선수의 실제 점 수다. 이전 선수·시간 드롭다운은 제거했다.
- ‘경기 흐름’은 ‘최근 경기 추이’로 메뉴·제목·버튼·가이드 용어를 통일했다. URL /tracking은 유지한다. 긴 설명 문단을 제거하고 실제 오류·빈 내역 안내와 조작 표시는 유지한다.
- 지표 비교는 색상과 부호를 함께 사용한다. 최근 경기 요약은 승 파랑, 패 빨강, 무 회색이다.
- 선수 비교와 지도 필터는 기존 응답을 사용하므로 선택마다 API 요청이 추가되지 않는다. 카탈로그 연결은 Map으로 O(M+R), 선수 지표 짝짓기는 O(M), 지도 필터는 O(S)다. 랭커 분류의 반복 find를 Map 조회로 바꿔 O(M²)에서 O(M)으로 줄였다.

## 운영 집계 유지

- 랭커 평균의 마지막 실제 집계는 Redis에 공유한다. 새 서버의 빈 임시 DB나 실패한 갱신으로 유효한 집계를 덮어쓰지 않는다.
- 보관 기한은 원래 랭킹 수집 시점과 API 자료 보관 기한으로 제한하며, 재조회로 기한이나 수집 시각을 연장하지 않는다. 새 수집이 완료되면 해당 실제 집계로 교체한다.
- 최근 24시간 집계가 있으면 새 인스턴스에서 전체 랭커를 다시 수집하지 않는다. 갱신은 공유 잠금으로 중복 실행을 막는다. 조회는 캐시 두 건의 O(1)이다.
- 2026-10-28 배포의 첫 인스턴스에는 2026-10-27에 실제 수집한 20명·480개 기록의 집계만 초기 자료로 동봉했다. 사용자 식별자·원시 경기·랭커 닉네임은 포함하지 않는다. 공유 캐시가 비었을 때만 사용하며 같은 보관 기한을 적용한다. 이후 수집한 집계가 우선한다.

## 비교 구분·포메이션·검색 간소화

- 선수 비교의 막대는 첫 번째 선수 파랑·두 번째 선수 보라로 고정한다. 우열마다 선수 색을 바꾸지 않는다. 차이 부호와 수치는 그대로 유지한다.
- 랭커·상대의 강점/보완점은 제목·개수·테두리가 있는 별도 영역으로 표시한다. 랭커의 나머지 지표에서는 위에서 강조한 항목을 제외한다. ‘최근 30경기’ 고정 안내를 반복하지 않고 실제 관측 경기 수를 유지한다.
- 포메이션은 최근 정상 종료 경기에서 확인된 등록 포지션을 사용한다. 공개 피드는 배치를 바꾸지 않고 해당 선수의 설정 연결에만 참고한다. 같은 자리에 다른 카드·강화의 출전 기록이 있으면 한 명만 골라 해당 자리에서 교체 표시한다. 없는 출전 조합은 만들지 않는다.
- 통합 분석(match_type=0)은 몰수승·몰수패를 포함한 최신순 30경기로 고정한다. 검색에서 포함 여부 선택을 제거한다. 전적·경기 목록은 몰수 포함이고 선수 세부 기록·랭커/상대 비교는 정상 종료 기록을 사용한다. 다른 모드를 사용하는 기존 API의 선택 옵션은 보존한다.
- 포메이션 선택은 Map으로 같은 자리의 기록만 O(P)에 연결한다. 상대 지표 집계 O(N×K), 강조 항목 정렬 O(K log K)이며 외부 API 호출이 추가되지 않는다.

## 피드 사진·신규 특성

- 선택한 피드의 미니페이스온을 우선 표시한다. 같은 선수의 다른 시즌 사진은 사용할 수 있지만 경기의 시즌·강화·등록 포지션·기록을 변경하지 않는다.
- 기본·획득 특성을 합쳐 실제 신규 특성만 중복 없이 최대 2개 표시한다. 아이콘 색상을 임의로 바꾸지 않는다.
- 특성 표시는 전술·코칭 연결과 분리한다. 같은 카드(SPID)·강화를 우선하고, 포지션만 다른 경우에도 피드 특성을 확인할 수 있다.
- 같은 카드의 다른 강화만 확인되면 ‘피드 10강’처럼 저장된 강화 출처를 표시한다. 후보가 여러 개이거나 다른 시즌이면 임의로 대입하지 않는다.
- 같은 카드·포지션은 강화가 달라도 저장된 기본·획득 특성, 훈련코치, 개인 전술과 참여도를 열람한다. ‘피드 저장 설정 · RF · 9강’처럼 출처를 구분한다. 다른 강화의 능력치를 경기 기록으로 옮기지 않으며 코칭 연결의 카드·강화·포지션 일치 검증은 유지한다.
- 선수 이름은 공식 메타데이터를 1시간마다 갱신한다. 실패하면 직전 정상 목록을 유지하고 1분 후 재시도한다. 새 시즌 카드가 누락되면 동일 선수 번호의 일관된 공식 이름이나 선택한 공식 피드 이름을 사용한다. 확인할 이름이 없으면 식별자 대신 ‘이름 확인 중’을 표시한다.
- 특성 조회는 피드 인덱스 구축 O(F), 선수별 O(1)이며 기존 스냅샷을 재사용한다.

## 몰수 경기의 실제 기록 (2026-10-29)

- 경기 결과·승률·최근 경기 추이의 시점은 정상 종료, 몰수승, 몰수패를 모두 포함한다.
- 플레이 지표는 중단 전 API에 남은 슈팅·패스·수비·선수 기록만 사용한다. 시도가 없는 성공률은 미확인으로 유지하고 없는 출전 기록을 만들지 않는다. 같은 최근 30경기의 마지막 추이 값과 현재 분석 지표가 일치한다.
- 정상 경기의 팀 득점은 자책골을 포함한 최종 점수를 유지한다. 몰수 경기는 goalTotal과 상대 ownGoal을 사용하며 몰수로 부여된 goalTotalDisplay 3:0은 득점·실점·GK 지표에 합산하지 않는다. 슈팅 득점 전환율은 항상 goalTotal / shootTotal이다. 최근 경기 목록의 최종 점수는 별도로 유지한다.
- 확보한 실제 API 응답에 정확한 종료 시각·출전 시간이 없어 마지막 슈팅 시각을 종료 시각으로 간주하거나 90분당 기록을 만들지 않는다. 경기당 기록은 제공된 기록의 경기당 평균이다.
- 랭커 평균 캐시는 v6로 구분한다. 기존 20명의 실제 확보 경기 598개(정상 480, 몰수승 101, 몰수패 17)로 같은 기준의 배포용 집계를 재계산했다. 원래 랭킹 조회 시각을 유지하고 인원별 동일 가중치로 계산한다.
- 최근 경기 추이는 이동 합계를 유지해 O(N×K)로 계산한다. 선수 비교 선택 목록은 긴 영문 시즌 설명을 줄이고 min-width·max-width를 지정해 좁은 화면의 선택 상자 고유 폭을 제한한다.

- 전체 패스 집계는 전체 성공·시도가 유효한 모든 경기로 계산한다. 유형별 성공률·사용 비중과 미분류 패스는 6유형의 합계가 검증된 동일한 경기 집합만 사용한다. 전체·유형의 경기 수와 분모를 분리해 누락 유형 때문에 전체 기록까지 버리지 않는다.
