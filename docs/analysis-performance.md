# 분석 조회 성능 설정

- 통합 분석은 몰수 경기를 포함한 모드별 최대 59개 기록만 조회한다. 최근 30경기와 30개 이동 집계 시점에 필요한 범위이며, 정상 종료 59개를 채우지 않는다.
- 이미 확보한 기록은 재사용하고, 새 기록만 추가 조회한다. 분석 직후 같은 기록을 다시 수집하는 작업은 실행하지 않는다.
- 경기 상세는 요청별 4개씩, 프로세스 전체 8개 작업자 안에서 병렬 조회한다. 결과는 API 목록의 원래 순서로 반환한다. 실패하면 다음 묶음을 예약하지 않으며 부분 성공을 완전한 표본으로 저장하지 않는다.
- HTTP 세션은 작업자별로 분리하고 조회 후 닫는다. 별도 프로세스의 호출 수는 이 프로세스의 제한에 합산되지 않는다.
- 경기·피드·선수 메타데이터 조회는 겹쳐 실행한다. 피드는 매 분석 시 공개 상태를 재확인하며 실패 시 이전 설정을 대신 연결하지 않는다.

## 호출 속도

`HABIT_LAB_NEXON_REQUESTS_PER_SECOND`의 기본값은 개발 키용 4이다. **서비스 단계 키를 실제로 사용하는 환경**에서는 40 등으로 설정한다. 실제 키가 개발용이면 앱이 별도로 서비스 단계로 등록되어 있어도 이 값을 높여서는 안 된다.

공식 한도: 개발 단계 5회/초, 서비스 단계 500회/초. 호출 제한 응답은 기존 공통 대기를 적용한다. 여러 서버 인스턴스나 다른 수집기가 같은 키를 쓰면 애플리케이션 전체 호출량을 함께 고려해야 한다.

HTTP 요청 수의 복잡도는 O(N)으로 유지되며, 동시 조회의 대기 시간은 대략 O(ceil(N/4) × 응답 지연)으로 줄어든다. 호출 간격 제한과 외부 서버 지연이 실제 하한이므로 모든 상황에서 10초를 보장하지 않는다. 10초 뒤 임의로 표본을 잘라 성공으로 반환하지 않는다.

## 검증 기준

최초 조회(경기 캐시가 없는 DB), 동일 조건 재조회, 새 경기 추가를 구분한다. 시간과 함께 다음 항목을 확인한다.

- 필요한 경기 수, 선택한 경기 ID의 해시, 지표의 해시
- 실제 상세 호출 수, 실패 여부, 피드 연결 상태
- 몰수 포함 성공률 분모 및 최근 경기 추이의 동일성

키·식별자 원문은 성능 보고서에 저장하지 않는다. 운영 배포 전 실제 서비스 단계 키 및 운영과 유사한 캐시 환경에서 재측정한다.
